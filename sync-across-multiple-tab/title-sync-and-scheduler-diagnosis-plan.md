# 任务计划：标题同步状态与调度表现诊断

## 目标
解释并修复标题同步状态在切到非 S1 标签页后不易看到，以及多帖子阅读过程中导航栏反复出现同步状态的原因。

## 关键问题
1. 切到非 S1 浏览器标签页时，所有 S1 标签页是否会足够及时地进入 `document.visibilityState === "hidden"`？
2. 详情页上看到的“同步中”来自后台 push 的共享 debounce，还是来自前台 freshness probe / follow-up？
3. 列表页同步完成后，详情页再次显示 `running -> success` 是否由单标签缓存、same-device 远端写入或前台探测造成？

## 决策
- 将本次诊断记录放在 `sync-across-multiple-tab/` 下，避免混入根目录旧设置迁移任务。
- 标题状态 owner 从“最早打开的存活 S1 标签页”改成“最近活跃 / 最近离开的 S1 标签页”，因为最早打开的后台页更容易被浏览器限流，也更不符合用户观察标签页标题的直觉。
- 保留前台 follow-up 作为真实检查 / 同步路径，但在导航栏视觉上区分 metadata 探测与真正同步执行。
