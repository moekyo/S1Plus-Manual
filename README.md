# S1 Plus - Stage1st 体验增强套件

> 当前文档基于当前分支的 `S1Plus.js` 源码整理。脚本元数据版本仍为 `v6.10.0`（最近发布日期 `2026-03-28`），但已包含尚未发布的多标签页同步重构、一级玻璃系统重构与文档更新。

## 项目简介

S1 Plus 是一个面向 Stage1st（S1）的用户脚本，目标是让论坛浏览更清爽、更高效、更可控。当前版本是单文件脚本（`S1Plus.js`），覆盖帖子/用户/楼层管理、阅读进度、收藏与标记、导航定制、图片查看、自动签到、跨设备同步等完整能力。

## 当前版本速览

- 代码基线：`v6.10.0` + 当前分支未发布改动
- 脚本版本字段：`6.10.0`

- 脚本入口：`S1Plus.js`
- 元数据匹配：`https://stage1st.com/2b/*`
- 存储方式：Greasemonkey API（`GM_getValue` / `GM_setValue`）
- 远程同步：GitHub Gist（`api.github.com` + `gist.githubusercontent.com`）

## 功能全景（按真实实现梳理）

### 1. 帖子、用户、楼层三层屏蔽体系

- 列表页一键屏蔽帖子（支持确认菜单中“顺便拉黑作者”）
- 标题规则屏蔽：支持关键字和正则，带风险检测与自动降级
- 楼层级屏蔽：可屏蔽单条回复，不必屏蔽整位用户
- 用户屏蔽：可选联动屏蔽其主题帖，支持备注
- 与论坛原生黑名单联动：支持同步添加/移除
- 论坛黑名单页导入：支持“导入本页到 S1 Plus”逐页迁移，并按 UID/用户名去重
- 本人楼层快捷编辑：在帖子工具栏提供“编辑当前回复”入口（仅在论坛原生允许编辑时显示）
- 可选自动隐藏“系统已屏蔽楼层”

### 2. 用户标记系统

- 帖内快速标记/编辑/删除
- 支持颜色标签
- 设置面板集中管理，支持导入/导出
- 标记信息跨页面刷新

### 3. 回复收藏系统

- 帖内一键收藏回复
- 收藏列表支持搜索与高亮
- 长文支持展开/收起
- 同步时可选“仅预览（默认）”或“完整正文”

### 4. 阅读进度系统

- 帖子页自动跟踪阅读楼层与页码
- 列表页显示阅读进度跳转按钮
- 帖内显示“当前阅读位置”标识（可关闭）
- 主楼楼层支持文本兜底（如“楼主”），仅主楼帖子也能稳定记录进度
- 清理模式：
  - 自动：按时间阈值（1个月/3个月/6个月/永不）
  - 手动：分组查看并按组删除
- 跨标签页实时刷新进度按钮
- 同帖多标签时采用“只前进不回退”策略，避免旧标签覆盖新进度
- 可见楼层临时为空时，按“最近一次可见楼层 -> 主楼兜底”保存进度，降低漏记概率

### 5. 图片体验增强

- 默认隐藏帖子图片（支持单图/整楼切换）
- 超大图限制（默认 `800x1200`，可自定义并恢复默认）
- S1 Plus 自定义图片查看器（可替代论坛原生）：
  - 滚轮行为可配置为缩放或上下滚动画布，可调整幅度、按当前模式恢复默认，并按鼠标/触控板信号平滑折算；支持拖拽平移、Esc 关闭
  - 同回帖多图切换
  - 切图加载失败自动重试（含原始 URL 回退兜底），弱网下切换稳定性更高
  - 完整显示、放大显示、新标签打开原图；放大显示可设置默认铺满宽度比例（60% - 100%）
  - 工具条放大/缩小/上下滚动支持长按连续动作
  - 支持“保存图片 / 保存全部图片”（同贴多图顺序批量下载，网络异常自动重试）
  - 深色模式下切图 loading 浮层、加载文字、转圈图标与取消按钮保持一致的暗色可读配色
  - 动画支持 `prefers-reduced-motion`
- 顶层设置面板、确认弹窗、手动同步选择/冲突、欢迎弹窗、S1 NUX 推荐、Token 过期提醒、阅读记录详情与图片查看器统一使用轻量磨砂玻璃分层和全屏蒙版；确认类弹窗使用独立、无边框且适配浅色/深色的 prompt 材质与蒙版，设置面板内的 Token 有效期日期配置作为面板内二级弹窗承载，不再额外叠加全局蒙版；Toast、浮动控件与右下角调试 FAB 保持一致的低透明玻璃质感；浅色/深色模式下都优先保证文字可读

### 6. 链接与导航增强

- 链接打开方式按来源独立控制（无总开关）：
  - 帖子/消息链接
  - 阅读进度跳转
  - 顶部导航/菜单
  - 帖子详情页链接（含自动补链）
  - 其他论坛链接
- 每个来源都支持三态：关闭 / 自动切换到新标签页 / 后台打开不切换
- 设置面板为“链接打开方式（新标签页）”提供标题右侧的内联问号帮助图标，按分类解释各项适用范围
- 自定义悬浮提示在目标节点被收起、重绘或移除时会自动关闭，减少快速切换设置或列表项刷新时的提示残留
- 帖子楼层工具栏中的原生快捷链接（如“只看该作者”“显示全部楼层”“正序/倒序浏览”“编辑当前回复”）保持原生打开行为，不受上述全局接管规则影响
- 纯文本 URL 自动识别并转为可点击链接（`http/https/www`）
- 自定义导航栏链接（增删改、排序）
- NUX 顶栏补充“帖子”快捷入口

### 7. 同步系统（核心能力）

- 本地导出/导入：完整备份/恢复
- 远程同步：GitHub Gist
- 同步数据结构：`version 5.0`，包含 `contentHash` 与 `baseContentHash`
- 启动同步 orchestrator：
  - 页面仍在新鲜窗口内时执行完整启动链路
  - 错过窗口时只顺延真正需要顺延的每日首次同步
  - 不会在旧页面上晚到补跑启动专属检查
- 自动检查路径：
  - 每日首次加载检查
  - 每次页面加载检查
  - 页面首次可见 / 回到前台检查
  - 页面持续可见时的低频轮询复查（独立开关，不再依赖"回到前台检查"总开关）
- 冲突判定：
  - baseline 三方比较优先
  - 时间戳仅作兜底（含时钟偏差保护）
- 自动合并：当仅阅读进度分歧时自动 merge 并回写云端
- 低打扰前台探测：
  - 先做 metadata 级远端 probe
  - 确认远端变化后再进入 follow-up safe sync
  - 命中阅读进度 pending / debounce / 初始化噪声窗口时会先 soft block，等待本地状态稳定
  - 支持区分远端写入来源（同会话写入 / 同设备写入 / 外部变更），减少跨标签页误报；该分类同样适用于后台阅读进度自动合并路径，使合并结果能区分静默、同设备通知与云端变化提示
- 多标签页保护：
  - 阅读进度区分“真实阅读”与初始化噪声
  - 后台打开帖子页默认保持被动，不轻易制造本地脏数据
  - 隐藏或冻结的后台标签页成为 shared sync owner 时，会主动补发待推送阅读进度，不必等切回前台才同步
  - 当前标签页 / 当前线程的局部脏状态不再轻易升级成全局暂停
- 并发控制：
  - 手动/后台/启动/前台补同步四类锁
  - 全局同步锁统一互斥
  - 锁心跳与失锁中止
  - 导航栏直接拉取 / 推送是用户显式覆盖操作：没有活动同步时立即执行；如果已有同步占用执行锁，则登记精确的 durable 手动意图并在导航栏保留用户选择的方向，当前执行完成后再请求确认，不删除正在运行任务的锁或心跳。跨标签页 authority 使用不可变的 per-request/per-transition GM records；旧代次不能覆盖或删除较新的显式方向，confirmation owner 通过 fencing token 收敛为单一有效 owner
- 稳定性机制：
  - 请求超时 + 重试
  - 自动同步熔断（连续失败暂停）
  - 冲突暂停门控
  - 前台 follow-up sync 补偿重试
  - same-session / same-device remote write 抑制
  - 跨页面待同步补发（含 bfcache 恢复）
  - 自动推送必须配置同步设备 ID，用于标记本机写入来源并降低同设备误报
- 可观测性：
  - 统一自动同步状态指示器（覆盖启动检查、前台检查、可见页轮询和后台自动同步）
  - 导航栏常驻同步提示（`本地改动待处理` / `本地数据较新` / `连续失败`，支持“处理/忽略本次”；手动同步进行中会显示“同步中...”，重复点击会提示稍候）
  - 同步诊断面板（设置页版本号三连击）
  - 扩展诊断字段（最近 probe、触发源、页面可见性、哈希摘要、cleanup 来源、阅读进度摘要、脏数据溯源、远端写入匹配种类、已应用 content hash 等）
  - Token 过期提醒（到期前 3 天）

### 8. 其他增强

- 自动签到（按 UID 隔离，多账号互不干扰）
- 指数退避重试（签到失败后自动延时重试）
- S1 NUX 搭配推荐（可关闭）
- 增强型悬浮控件（与右下角调试 FAB 保持一致的低透明玻璃质感）
- 新版关闭按钮弹窗交互统一（设置面板 / Token 有效期 / 阅读记录详情 / 图片查看器）：支持 `Esc` 关闭，并在 S1 NUX 下保持稳定的开关动画与焦点高亮表现

## 脚本架构分析（当前实现）

### 单文件架构

- 全部逻辑集中在 `S1Plus.js`
- 通过函数分区组织：
  - 安全与清洗
  - 数据存储与缓存
  - 同步引擎
  - 设置面板与交互
  - 页面增强与观察器

### 数据模型（核心持久化）

- `s1p_settings`：全局设置
- `s1p_blocked_threads`：屏蔽帖子
- `s1p_blocked_users`：屏蔽用户
- `s1p_blocked_posts`：屏蔽楼层
- `s1p_user_tags`：用户标记
- `s1p_bookmarked_replies`：收藏
- `s1p_title_filter_rules`：标题规则
- `s1p_read_progress`：阅读进度

### 安全策略

- URL 白名单策略（收紧协议与目标）
- `sanitizeHtmlFragment` 统一清洗受控 HTML
- `sanitizeRecordObject` 过滤原型链污染键
- 标题正则风险检测（高风险自动降级关键字匹配）

### 性能策略

- 设置与核心数据 1 秒 TTL 缓存
- DOM 变更增量处理（MutationObserver scope 化）
- 高频集合匹配使用 `Set`
- 阅读进度内存缓冲 + 批量落盘

   - macOS 可直接使用 `S1Plus-Local-Mac.user.js`
   - Windows 可直接使用 `S1Plus-Local-Windows.user.js`

### 快速上手

1. 在导航栏打开 `S1 Plus 设置`
2. 依次配置：通用设置 / 屏蔽 / 标记 / 收藏 / 导航 / 同步
3. 若使用云同步：填写 Gist ID + PAT，点击“保存设置”；如果开启“自动推送”，还需要填写同步设备 ID
4. 首次建议手动同步一次确认链路正常

## 同步相关说明

- “设置同步”页的配置项是**手动保存模式**，改完需点“保存设置”
- 导航栏同步按钮点击或悬停都会打开同一个“推送/拉取”菜单；点击只是键盘/触摸等场景的备用入口，不会直接执行同步。菜单里的两个方向按钮拥有最高的用户意图优先级：没有活动同步时立即按你点的方向执行；如果当前同步尚未结束，会先登记该方向并显示待处理，当前同步完成后再弹出确认，不会删除正在运行任务的锁、心跳或待同步数据
- 设置页和冲突提示中的手动同步会先做安全检查，必要时让你选择推送、拉取或取消
- “推送”会用本地数据覆盖云端，“拉取”会用云端数据覆盖本地；直接选择时请确认当前要保留哪一端
- 同步执行期间不要求页面一直保持前台：可以切到其他标签页、页面或软件，但不要关闭、刷新、后退或跳转发起同步的那个 S1 标签页；如果延迟弹出拉取/推送确认框，需要回到拥有确认权的 S1 页面手动确认
- 发生冲突时自动同步会暂停，需手动决策
- 同步设备 ID 只约束“自动推送”：开启该开关时必须填写，用于标记这台设备写入云端的来源；仅开启自动拉取或手动同步时不强制填写
- 如果没有填写同步设备 ID 就打开“自动推送”，设置面板会立即提示；提示消失时若仍未填写，开关会自动回到关闭状态，保存时也会再次兜底校验
- “每日首次加载时同步”“每次页面加载时检查同步”“回到前台检查”现在是分工更明确的几条自动拉取路径
- 历史上如果你曾通过“关闭每日首次加载时同步”来使用“每次加载检查”，脚本会在设置归一化阶段自动迁移到新的独立开关
- 页面首次可见、回到前台、从 bfcache 恢复和页面持续可见时，会先做轻量远端 probe；这类 probe 不会因为本地状态干净而跳过远端 `updated_at` 检查，只有确认云端变更后才继续 follow-up safe sync
- 标签页标题同步状态只用于提示本地数据上传安全性：轻量远端 probe 和云端拉取不会点亮标题；无变化、冷却跳过或等值复查时标题保持原样，只有本地推送、推送失败或需要处理的冲突才显示标题提示
- “每次页面加载时检查同步”同样走启动同步锁，同一时刻仅允许一个标签页执行检查，其余标签页会自动跳过，避免并发请求风暴
- 启动同步如果错过页面新鲜窗口，会顺延每日首次同步到下一个新页面，而不会在当前旧页面突然补跑启动专属检查
- 设置页和冲突流程中的手动同步在需要用户弹窗决策时会释放锁，确认操作后再重获锁并重校验云端快照；导航栏手动方向在等待已有同步边界时使用独立的 durable intent，确认框本身不占执行锁
- 当前标签页的阅读进度 pending / debounce / 初始化噪声会先进入 soft block，不会直接把全局自动同步升级成冲突
- 导航栏同步指示器会统一反映启动同步、前台 follow-up sync、可见页轮询与后台自动同步，不再只盯后台推送
- 导航栏同步指示器用同一组三箭头 SVG 表示真正的待推送 / 待拉取与同步中：pending 只显示前两枚并对齐 running 队列相位，进入 running 后接入第三枚并流动；轻量远端 probe、等值复查、推送完成后的云端确认和前台复查等待都用放大镜表达“正在确认云端状态”。快速完成的前台 probe 不会闪现放大镜，慢 probe 才显示检查状态
- 自动同步暂停时，导航栏会显示常驻提示，区分“本地改动待处理 / 本地数据较新 / 连续失败”三类状态
- 常驻提示的“处理”会触发手动同步；“忽略本次”为会话级生效（刷新后恢复）
- 前台探测命中远端更新时间变化后，如果 follow-up sync 因锁占用或本地待写入等原因被暂缓，会先显示放大镜等待复查，不提前误标为待拉取；只有 full sync 真正决策为拉取时才显示向下箭头
- 自动拉取、强制拉取和阅读进度自动合并后的导入统一走同一套刷新策略；需要自动刷新时会先保留约 3 秒提示，减少“实际已同步但页面看起来没变化”和“提示还没看清就刷新”的情况
- 自动同步指示器调试面板默认不显示，但调试框架已保留；需要时可在控制台手动启用：
  - `window.__s1pAutoSyncIndicatorDebug.showPanel()`
  - `window.__s1pAutoSyncIndicatorDebug.hidePanel()`
  - `window.__s1pAutoSyncIndicatorDebug.clear()`
- 调试面板只覆盖导航指示器预览，不会改写真实同步状态；面板内显示的“实际 phase/source/operation”和“实际显示”仍来自当前真实同步状态；“常看转场”包含 pending push/pull → running 与 probe → pull 等固定预览路径
- 右下角“调试控制台”是另一个浮动面板，通过设置页底部版本区域悬停 4 秒后出现的小点切换；设置页底部版本号三连击打开的是当前设置窗口内的“同步诊断信息”，不是右下角浮动控制台。两个右下角浮动面板共用容器但状态独立，同时打开时会上下堆叠，不会互相改写同步状态或日志状态
- 统一调试面板外层使用低强度磨砂玻璃，保留背后论坛内容可辨识；指示器调试 tab 另有单一无边框浅底内容区，用来保证状态文字和按钮在复杂背景下仍清晰可读
- 右下角调试控制台会统一清理日志消息里重复的本地时间前缀，列表显示和复制内容都只保留一套行首时间
- 调试控制台的日志在同标签页刷新后会自动恢复（通过 sessionStorage），关闭标签页后清除；收集器仅在面板打开时运行，面板隐藏后停止拦截 console
- 脚本会在设置归一化阶段自动迁移并清理历史遗留配置键，仅保留当前版本支持的配置项
- 更换 PAT 后会先做一次轻量凭据校验，若认证被拒绝（401/403）会先提示并中止本次首次同步检查

## 常见问题

### 数据会不会丢失？

本地数据默认保存在浏览器中。启用远程同步后，会额外保存一份到你的 Gist。

### 为什么有些功能看起来没生效？

优先检查：

- 对应总开关是否开启（例如“启用通用设置”“启用帖子屏蔽”）
- 脚本管理器中脚本是否启用
- 是否与当前页面类型匹配（列表页 / 帖子页 / 个人页）

### 同步异常怎么排查？

- 检查 Token/Gist/网络
- 需要观察导航栏自动同步指示器动画或状态切换时，可先执行 `window.__s1pAutoSyncIndicatorDebug.showPanel()` 打开隐藏的调试面板
- 调试结束后可执行 `window.__s1pAutoSyncIndicatorDebug.hidePanel()` 隐藏面板，或执行 `window.__s1pAutoSyncIndicatorDebug.clear()` 恢复真实指示器显示
- 打开同步诊断（设置页底部版本号三连击）查看失败原因
