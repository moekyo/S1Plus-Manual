# UI 组件展示面板 — 设计决策记录

> 将 S1Plus 所有自定义 UI 控件放入调试面板的一个新标签页，方便后续调整样式时快速查看效果。

---

## 1. 展示方式

**决策**: 交互展示型 — 不仅渲染组件，还可以在面板内操作它们（点按钮、拨开关、输入文字、触发弹窗等），但**不绑定真实业务逻辑**，仅做视觉演示。

**原因**:
- 静态目录型太弱，无法看到实际渲染效果
- 纯实时预览型缺少交互反馈，看不出 disabled/focus/hover 等状态
- 交互展示型用 dummy 数据隔离，不会影响真实设置

---

## 2. 展示范围

**决策**: 全部 27 大类组件，分为两种处理策略：

| 策略 | 组件类型 | 说明 |
|------|---------|------|
| 虚拟渲染 + 隔离交互 | 按钮、开关、输入框、分段控制器、日期选择器、颜色选择器、徽章、卡片、列表、确认栏、可折叠、工具提示、内联编辑、加载指示器 | 真实 CSS 样式渲染，交互仅在面板内生效 |
| "打开预览"按钮 | 模态框、弹出层、图片查看器 | 点击按钮打开真实弹窗查看效果 |

**原因**: 模态框/弹出层依赖全局 DOM 挂载位置，无法嵌入面板内正常展示。

---

## 3. 面板布局

**决策**: 左侧分类导航 + 右侧组件展示，全部在 `s1p-debug-tab-pane` 内部。

```
┌─────────────────────────────────────┐
│ s1p-debug-tab-pane                  │
│ ┌──────────┬──────────────────────┐ │
│ │ 侧边栏    │ 右侧内容区            │ │
│ │ (130px)  │ (flex:1, overflow:auto)│ │
│ │          │                      │ │
│ │ • 按钮   │  [组件矩阵渲染区域]    │ │
│ │ • 开关   │                      │ │
│ │ • ...   │                      │ │
│ │ • 弹窗预览│                      │ │
│ └──────────┴──────────────────────┘ │
└─────────────────────────────────────┘
```

**原因**:
- 16 个分类用顶部标签页放不下
- 侧边栏垂直排列更紧凑，左侧 130px 足够放下短中文标签
- 避免调试面板宽度不足的问题

---

## 4. 类别划分

**决策**: 16 个大类，每个大类在侧边栏占一行。

```
按钮 / 开关 / 分段控制器 / 输入框 / 日期选择器 / 颜色选择器
提示通知 / 徽章标签 / 卡片分组 / 列表条目 / 确认栏 / 可折叠
工具提示 / 内联编辑 / 加载指示器 / 弹窗预览
```

**与 UI-COMPONENTS.md 的映射关系**:
- 合并了"模态对话框"和"弹出层"为"弹窗预览"（都只放打开按钮）
- NUX 主题兼容修正不纳入（属于运行时修正逻辑，非 UI 控件本身）
- Debug 面板子控件不纳入（展示面板自身就是 debug 面板的一部分，避免循环）
- 帖子工具栏图标不纳入（依赖帖子 DOM 上下文太深）
- 导航栏组件不纳入（依赖 navbar DOM 上下文太深）

---

## 5. 组件展示粒度

**决策**: 完整矩阵型 — 每种变体组合都展示。

以按钮为例展示：
- 默认 / 悬停态(强制CSS) / 禁用态
- 小按钮 / 小按钮悬停 / 小按钮禁用
- 危险按钮悬停 / 红色按钮悬停
- 确认栏按钮 / 确认栏悬停
- 内联切换按钮 / 内联切换悬停

以开关为例展示：
- 开启 / 关闭
- 开启禁用 / 关闭禁用
- 条目小开关(开/关)
- 功能大开关

**状态模拟方式**:
- `disabled` 属性 → 原生禁用态
- `.s1p-ui-force-hover` → 通过 `!important` 覆盖应用 hover 样式
- `.s1p-ui-force-focus` → 通过 `!important` 覆盖应用 focus 样式
- 真实交互 → checkbox 点击、输入框聚焦、弹窗触发等用原生行为

---

## 6. 弹窗入口位置

**决策**: 弹窗类的入口按钮放在各自分类的内容区内（如"弹窗预览"分类），与其他分类的展示区域隔离，不混在一起。

```
弹窗预览分类:
  [打开确认模态框预览]
  [打开输入模态框预览]
  [打开高级确认弹窗预览]
  [打开欢迎弹窗预览]
  [打开图片查看器预览(示例URL)]
```

---

## 7. 标签页位置

**决策**: 作为调试面板的第 4 个标签页新增"UI 组件"，不替换现有标签。

```
[日志]  [诊断信息]  [指示器调试]  [UI 组件]
```

---

## 8. 实现方式

**决策**: 在 `S1Plus.js` 内直接新增 `createDebugUIComponentsTabContent()` 函数，样式以嵌入式 `<style>` 方式写在函数内，不修改全局 CSS。

**原因**: 避免全局 CSS 污染；面板已受 `#s1p-debug-unified-panel` 作用域限制。

---

## 9. 已知问题与修复记录

- 调试面板视觉统一：展示面板侧边栏、展示项背景、分隔线和标题字号已改为复用 `#s1p-debug-unified-panel` 的玻璃表面变量，避免与日志/诊断标签页割裂。
- 真实组件结构对齐：确认栏改用 `s1p-confirm-action-btn s1p-confirm` / `s1p-confirm-action-btn s1p-cancel` 圆形图标按钮；功能大开关和设置分组改回真实 `s1p-settings-group` / `s1p-settings-item` 层级；分段控制器移除重复内联样式，仅保留静态 slider 宽度用于预览。
- 弹窗预览调用修复：确认弹窗、输入弹窗、高级确认弹窗、日期选择器、Toast 和图片查看器均已按当前实现的真实函数签名调用。
- 欢迎弹窗预览修复：不再调用受版本标记控制的 `showFirstTimeWelcomeIfNeeded()`，改用普通确认弹窗展示入口样式，保证点击必有反馈。
- 图片查看器预览修复：`openS1pImageViewer()` 现在传入字符串 URL；面板内仍使用 picsum.photos 示例图，实际加载依赖用户脚本的 `@connect` 授权环境。
