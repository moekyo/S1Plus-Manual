# 标签页标题同步状态提示

## 功能概述

开启后，当所有 S1 标签页都不在前台时，排在最前面的标签页标题会在同步发生时显示状态提示（同步中/成功/失败/冲突）。

## 设置入口

设置面板 → 设置同步 → 状态显示 → **显示标签页标题同步状态**（开关）

设置项 `syncShowTitleSyncStatus`，默认开启，会随设置同步到其他设备。

## 状态与标题前缀

### 同步中 (running)

标题前缀 `[同步中.]` → `[同步中..]` → `[同步中...]` 循环，间隔 500ms，模拟"正在同步"的动画效果。

### 同步成功 (success)

标题前缀 `[同步成功]`，持续 2 分钟后自动消失。

### 同步失败 (failure)

标题前缀 `[同步失败]`，持续 5 分钟后自动消失。

### 冲突 (conflict)

标题前缀 `[冲突]`，持续 10 分钟后自动消失。

### 待命/待处理 (idle/pending)

不显示前缀，标题恢复原样。

## 多标签页协调

| 场景 | 表现 |
|------|------|
| 有标签页在前台 | **所有**标签页都不显示同步状态 |
| 全部在后台，单标签 | 该标签显示 |
| 全部在后台，多标签 | 仅 tabId 字母序排第一的标签（leader）显示 |
| leader 关闭 | 下一个标签自动接替显示 |
| 关闭开关 | 全部不显示，轮询停止 |

## 技术实现

### 跨标签注册表

- GM 存储 key：`s1p_sync_title_tabs`
- 每个标签页以 `SETTINGS_CROSS_TAB_SIGNAL_SOURCE_ID`（格式 `s1p_tab_{timestamp}_{random}`）作为唯一标识
- 注册表记录每标签的 `visible` 状态和 `ts` 时间戳
- 超过 2 分钟未更新的标签自动清理（死标签回收）
- 标签页关闭时（`pagehide`）主动注销

### 状态同步

- 通过 `GM_addValueChangeListener(AUTO_SYNC_INDICATOR_STATE_KEY)` 监听同步状态变化
- 通过 `GM_addValueChangeListener(SYNC_TITLE_TABS_KEY)` 监听注册表变化（其他标签打开/关闭/切前台）
- `visibilitychange` / `focus` / `pageshow` 事件触发状态刷新
- 30 秒轮询兜底（仅在 `syncTitleEnabled === true` 时运行，确保 TTL 到期后自动清理）

### 文件改动

| 文件 | 改动 |
|------|------|
| `S1Plus.js` | 新增常量、变量、函数，修改标题设置逻辑，新增设置面板开关 |

### 开关联动

- 当远程同步关闭时，该开关自动禁用
- 设置变更时跨标签同步，自动重新决策

## 边界情况

1. **标签页崩溃**：注册表 TTL 机制自动清理死标签（2 分钟超时）
2. **标题为空**：`lastAppliedPageBaseTitle` 在 `applyInterfaceCustomizations` 中设置，确保有内容
3. **动画与前台**：前台标签不启动动画，避免无意义的 CPU 消耗
4. **设置同步**：开关状态随设置同步到其他设备，但注册表是本地的，不同步
